// The store/draw confirm cue, SHIPPED HERE AS OF 2026-08-26.
//
// doSwap has always asked for "rs_fx_holster" or "rs_allclear_ready" by
// name, and CVARINFO's own note claimed that was fine because "whichever
// loaded weapon pack happens to define them supplies them". Only one thing
// on disk anywhere ever defined either name: RS_Main's SNDINFO -- and
// RS_Main is not part of this family and is not a declared dependency of
// this pk3. GZDoom resolves an undefined sound to SILENCE rather than to an
// error, so the confirm sound had simply never played for anyone running
// these mods without RS_Main, and nothing said so. A cvar, a menu row and a
// style selector all existed for a cue that could not sound.
//
// OWN LOGICAL NAMES AND OWN LUMP NAMES, deliberately -- exactly the pattern
// the flashlight click set below already follows, and for the same reason:
// this pk3 must not need any other pk3 loaded to have a sound, and must not
// silently override a lump another pk3 owns. RSHP* is this repo's prefix;
// RS_Holsters ships the identical audio under RSHO* so the two siblings do
// not collide with each other either.
//
// Audio source: RS_Main's Sounds/combatfx/foley/HOLSTR{,2,3} (the $random
// 3-variant holster clunk) and Sounds/combatfx/allclear/READYBP (the
// li-gnrcwpn plasma ready beep). Copied, not referenced -- same author, same
// project family.
$random rs_hardpoint_fx_store {
	rs_hardpoint_fx_store1
	rs_hardpoint_fx_store2
	rs_hardpoint_fx_store3	}

rs_hardpoint_fx_store1	RSHPHOL1
rs_hardpoint_fx_store2	RSHPHOL2
rs_hardpoint_fx_store3	RSHPHOL3
$volume rs_hardpoint_fx_store 0.7

// The alternate confirm style (rs_hardpoint_sound_style 1): a short cadence
// beep instead of a mechanical clunk.
rs_hardpoint_fx_ready	RSHPRDY
$volume rs_hardpoint_fx_ready 0.65
